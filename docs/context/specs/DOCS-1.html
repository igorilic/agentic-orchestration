DOCS-1: Docs, plans and specs in HTML

October 18, 2026 · Proposed

Problem

Agents write docs, plans and specs as Markdown. They should be HTML in the dark mode of the Spotlight design system, in every project the harness reaches. The design system is licensed and stays uncommitted. It lives in a gitignored skills/spotlight-design/, which make install copies to both tools like any skill. Each project links it in as a gitignored docs/.design.

Out of scope: converting other projects’ existing docs (their call, one pandoc run each); Claude’s own plan-mode files; files a tool reads as Markdown (README, CONTRIBUTING, CLAUDE.md, AGENTS.md, SKILL.md, CURRENT_SPRINT.md, PR/MR bodies, Obsidian notes); resuming a pipeline whose spec is still .md (rename it); committing any part of the design system, inlined CSS included.

Acceptance criteria

  • AC-1: Given run github-feature, when the plan stage runs, then the spec is docs/context/specs/<id>.html, its <h3>Step n headings set the steps, and the approval prompt shows it as text with no tags.
  • AC-2: Given run gitlab-incident <id>, then the report is <id>-incident.html, it is shown as text, and the fix is planned from it.
  • AC-3: Given a spec file x.md or x.html, then the pipeline id is x.
  • AC-4: Given install project, then ARCHITECTURE, CONVENTIONS, GLOSSARY and specs/templates/doc.html are dark HTML linking .design/styles.css, CURRENT_SPRINT stays Markdown, docs/.design links to the installed spotlight-design skill if there is one (an existing path is kept), and .gitignore gets docs/.design.
  • AC-5: Given the skills and both instruction files, then every doc they produce is .html, and the instructions carry one rule: HTML docs from the template, dark Spotlight look (not its demo voice), Markdown only where a tool reads it.
  • AC-6: Given this repo, then PAPER, ARCHITECTURE, ADRs 001–003, the specs and docs/superpowers/ are HTML with the same text, no link points at a moved .md, and the doc tests read the HTML.

Steps

Step 1

Test (AC-1, AC-3), tests/pipeline-safety.bats: the stub plans <h3>Step 1</h3><h3>Step 2</h3>; run github-feature toy.md writes specs/toy.html, runs two step stages, and prints “Step 1” but no <h3>; toy.html as input also gives id toy.
Implement: .html spec, count <h3…>Step n, a show_doc that strips tags, decodes &lt; &gt; &amp; and squeezes blank lines; id = basename minus its extension.
Files: lib/pipeline-core.sh, lib/pipelines.sh, tests/pipeline-safety.bats

Step 2

Test (AC-2): gitlab-incident INC-9 writes and shows INC-9-incident.html as text, and plans with /plan docs/context/specs/INC-9-incident.html.
Implement: the report path, shown through show_doc.
Files: lib/pipelines.sh, tests/pipeline-safety.bats

Step 3

Test (AC-4), tests/install.bats: the four HTML scaffolds exist with class="dark" and the .design/styles.css link; CURRENT_SPRINT.md unchanged; with $CLAUDE_HOME/skills/spotlight-design present, docs/.design resolves to it; a pre-existing docs/.design is untouched; without the skill there is no link and no error; .gitignore lists docs/.design.
Implement: one skeleton function for the scaffolds; link the first of the Claude and Copilot skill dirs that exists.
Files: lib/install-project.sh, tests/install.bats

Step 4

Test (AC-5), new tests/docs-html.bats: no skill or instruction file names a .md spec, incident report, ADR, ticket spec or FINDINGS; the plan skill names <h3>Step n</h3> (the pipeline’s contract); both instruction files name docs/.design/styles.css and the template.
Implement: the plan, incident, adr (numbering globs any extension), ticket and explore skills; one line in each instruction file.
Files: skills/{plan,incident,adr,ticket,explore}/SKILL.md, instructions/*.md, tests/docs-html.bats

Step 5

Test (AC-6), tests/docs-html.bats: the only tracked .md files are README, CONTRIBUTING, AGENTS, CURRENT_SPRINT, the instructions and SKILL.md files; no tracked file links a moved .md. The doc tests in no-legacy, install and install-copilot read the .html and check the same facts.
Implement: pandoc -f gfm each doc into the template (one-off, not committed); fix the links; add this repo’s specs/templates/doc.html; README and ARCHITECTURE say .html and docs/.design.
Files: PAPER.html, docs/**/*.html, README.md, CONTRIBUTING.md, tests/*.bats

Assumptions

  • Without the design system (fresh clone, CI, another machine) docs render as plain dark HTML. That is the price of not committing it.
  • I set disable-model-invocation: true in the local design system’s SKILL.md. Otherwise it would offer itself for product UIs in your other projects. /spotlight-design still works.
  • Existing tests change only in fixtures and paths (### Step → <h3>, .md → .html). They check the same facts. The guard will ask at those commits.
  • HTML specs cost each step session more tokens to read than Markdown did.

Done when

Every AC has a test and ./.anw/verify is green. Then you run make install and open a spec in a browser.
